# 版156 の決まり（実装したもの・最終）

現場入力（antenna_genba）の「保存」は、保存先フォルダの `管理番号.json` を丸ごと書き替える。
PCで写真・図面・積算を入れた戸別を書き潰さないために、書く前にファイルを読んで融合する。

## 3つの土台
| 名前 | 何か | どこから |
|---|---|---|
| **控え** `_fileBase` | そのとき戸別ファイルに入っていた中身（写真はIDだけ） | 📂 で読み込んだとき／自分が書けたとき |
| **台帳の控え** `_rcSrc` | そのとき受付台帳から入れた値 | 受付台帳を取り込んで開いたとき（前からある） |
| **作りたての既定値** | `freshModel()` の中身 | いつでも作れる |

## 融合の決め方（上から順）
0. **門番** … 戸別ファイルでなければ何もしない。管理番号が違えば **止める**。
1. **写真** … 必ず和集合。減ったら例外で落とす。別名ファイルの写真も足す。
2. **工程の印**（下見・ビラ・工事完了・同意書・完了書）
   - 控えあり → 控えと違う方を採る（**現場が取り消したら、必ず残る**）
   - 控えなし・台帳の控えあり → 台帳と違えば現場（＝現場が取り消した）／同じならPC
   - どちらも無い → 印が付いている方を採る（**PCの印を消さない**）
3. **TVの台数と部屋** … 5つまとめて採る（ばらばらに採ると食い違う）。最後に必ずそろえる。
4. **測定値** … 控えで見分ける。控えなしは「値が入っている方」。
5. **石綿** … アパート（2世帯以上）は **いつもPC**（建物で1つ）。戸建ては項目ごとに見分ける。
   控えなしは「作りたての既定値のままか」で見る（既定が level3・siding なので「空か」では足りない）。
6. **地図のキー・図面の注記** … 中のキー／idごと。控えにあって現場に無いものは復活させない。
7. **PCだけの欄**（数量の直し・機材の位置・諸経費・アパート・現場に欄が無いもの）… いつもPC。
8. **残りの欄**
   - 控えあり → 3つ見比べ。片方だけ違えばそちら。両方違えば、日時と備考は**1件保存のとき聞く**
     （既定はPC）、ほかは現場。
   - 控えなし → 台帳の控えで見分ける。分からなければ
     **「現場が触っていない（空・作りたてのまま）ところはPCを残す」**。
9. **仕上げ** … TVをそろえ、印の無い日時を空にし、状態と工事完了を合わせる。
   工事完了が外れていて状態が完了のときは、**現場が取り消したときだけ** 進行中に下げる。

## 書かない守り
- **G1** … この端末で何も入力していない戸別（`_touched` が立っていない・写真も無い）は、
  そもそもファイルを書き替えない。判定は `M._touched = true` より **前**。
  相手のファイルを読めないスマホ・共有・ダウンロードでも効く、唯一の守り。
- **写真の歯止め**
  - 控え／写真IDの副本が知っている写真が手元に無いとき、
    **相手を読めない道（共有・ダウンロード）では保存しない**。
    読める道（フォルダ・ファイルを選ぶ窓）は、読んで和集合にするので止めない
    （止めると1回保存したあと2回目が保存できない）。フォルダにファイルが無いときは止める。
  - 読めたファイルの写真が1枚でも落ちるなら書かない（融合に穴があっても止まる）。
  - PCのファイルに入っている写真は、現場の画面では消せない。
- **【見るだけ】の関門**（版155から）… PCに中身がある戸別は既定で閲覧のみ。
  進むときは消えるものを並べて確かめる。

## 版155 との違い（なぜ変えたか）
版155 は「作りたてと同じ値＝まだ何も入れていない」で決めていた。
これでは「現場でわざと消した・既定に戻した」を見分けられず、**工事完了の取り消しが復活**し
（完了の判定に直結）、PCの間違いを現場から直せなかった。実測で確認した。
版156 は控えで見分ける。ただし控えが無いときに「いつも現場が勝つ」にすると、
いちど直した不具合（工事の時刻が往復で消える・PCで選んだ積算が既定値に戻る・
PCの下見の印が消える）が戻るので、台帳の控えと作りたての既定値を二段目の手がかりにした。
